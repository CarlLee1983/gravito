# Gravito v2.0.0 Migration Guide

## Quick Start

Most upgrades require two steps:

1. Update `peerDependencies` in your `package.json` to the new major ranges (e.g. `"@gravito/core": "^3.0.0"`).
2. Replace error-message string checks with typed `instanceof` checks:
   ```typescript
   // Before
   catch (e) { if (e.message.includes('connection')) { ... } }

   // After
   catch (e) { if (e instanceof DatabaseException && e.code === 'db.connection_failed') { ... } }
   ```

If you are only consuming Orbit APIs (not catching errors by message string), most of your code will work without changes after updating `peerDependencies`.

## Breaking Changes

### 2a. Error Handling — Unified Exception Hierarchy (Phase 16)

All Orbit errors now extend `GravitoException` with three new fields: `.code`, `.status`, and `.cause`.

**Error hierarchy:**

```
GravitoException (abstract, base)
├── InfrastructureException (abstract, I/O errors — adds .retryable)
│   ├── DatabaseException
│   ├── CacheException
│   ├── QueueException
│   ├── NetworkException
│   └── ...one per I/O Orbit
└── DomainException (abstract, business rule violations)
    └── ...Satellite-defined errors
```

**Before:**

```typescript
// Orbit threw generic Error
throw new Error('Database connection failed')

// Caller matched by message string
try {
  await atlas.query(sql)
} catch (e) {
  if (e instanceof Error && e.message.includes('connection')) {
    // handle connection failure
  }
}
```

**After:**

```typescript
// Orbit throws typed exception
throw new DatabaseException(503, 'db.connection_failed', { cause: originalError })

// Caller matches by type + code
try {
  await atlas.query(sql)
} catch (e) {
  if (e instanceof DatabaseException && e.code === 'db.connection_failed') {
    // handle connection failure
    // e.status === 503
    // e.retryable === false
    // e.cause === originalError
  }
}
```

**Key details:**

- `instanceof` checks work correctly across ESM/CJS module boundaries. All error constructors call `Object.setPrototypeOf(this, new.target.prototype)`.
- Use `.code` (string, e.g. `'db.connection_failed'`) for programmatic handling — not `.message`.
- `.status` is an HTTP-compatible numeric status code (e.g. `503`, `422`).
- `.retryable` is available on all `InfrastructureException` subclasses. When `true`, the error is safe to retry.

**Affected packages:** `@gravito/core`, `@gravito/atlas`, `@gravito/plasma`, `@gravito/signal`, `@gravito/stream`, `@gravito/monitor`, `@gravito/beam`, `@gravito/sentinel`, `@gravito/fortify`, and all other I/O Orbits.

### 2b. Resilience Primitives (Phase 17)

Three duplicate `CircuitBreaker` implementations have been consolidated into `@gravito/resilience`. Two new composable primitives are available.

**New: `withRetry`**

```typescript
import { withRetry } from '@gravito/resilience'

// IMPORTANT: requires explicit idempotent:true flag
// Never wrap atlas.transactionWithRetry — it already retries internally
const result = await withRetry(
  () => atlas.query('SELECT ...'),
  { idempotent: true, maxAttempts: 3 }
)
```

**New: `withResilience`**

Composes timeout + circuit breaker + retry in the correct order (timeout outermost, retry innermost):

```typescript
import { withResilience } from '@gravito/resilience'

const result = await withResilience(
  () => atlas.query(sql),
  {
    timeout: 5000,
    circuitBreaker: { name: 'atlas', failureThreshold: 5, resetTimeout: 30_000 },
    retry: { idempotent: true, maxAttempts: 3, baseDelayMs: 200 },
  }
)
```

**New exception types:**

- `CircuitOpenException` — thrown when a circuit breaker is in the OPEN state.
  ```
  e.code === 'resilience.circuit_open'
  e.status === 503
  e.retryable === false
  ```
- `RetryExhaustedException` — thrown after all retry attempts have failed.
  ```
  e.code === 'resilience.retry_exhausted'
  e.status === 503
  e.cause === lastFailedError
  ```

**Before (manual try/catch for circuit open):**

```typescript
try {
  await callOrbit()
} catch (e) {
  if (e.message === 'Circuit breaker is open') {
    // handle manually
  }
}
```

**After (typed exception check):**

```typescript
import { CircuitOpenException } from '@gravito/resilience'

try {
  await callOrbit()
} catch (e) {
  if (e instanceof CircuitOpenException) {
    // circuit is open — e.code === 'resilience.circuit_open'
  }
}
```

### 2c. Graceful Degradation (Phase 20)

`OrbitDegradationManager` provides typed fallback when a circuit breaker is open, instead of requiring manual `try/catch` around every `CircuitOpenException`.

**Before (manual fallback on circuit open):**

```typescript
import { CircuitOpenException } from '@gravito/resilience'

try {
  const products = await withResilience(() => atlas.query(sql), policy)
  return products
} catch (e) {
  if (e instanceof CircuitOpenException) {
    return cachedProducts // manual fallback
  }
  throw e
}
```

**After (managed fallback with TTL caching):**

```typescript
import { OrbitDegradationManager } from '@gravito/resilience'

const mgr = new OrbitDegradationManager()

mgr.registerFallback('atlas', {
  fn: () => cachedProducts,
  ttl: 60_000, // cache fallback result for 60 seconds
})

const result = await mgr.execute('atlas', () => withResilience(() => atlas.query(sql), policy))

if (result.degraded) {
  // result.source === 'fallback'
  console.warn('Atlas circuit open — using fallback data')
}

return result.value
```

**`DegradedResult<T>` interface:**

```typescript
interface DegradedResult<T> {
  value: T                    // the returned value (live or fallback)
  degraded: boolean           // true when fallback path was used
  source: 'live' | 'fallback' // origin of the value
}
```

**Test environment behavior (D-05):**

In `NODE_ENV=test`, `OrbitDegradationManager` does NOT intercept `CircuitOpenException`. The exception propagates as-is. This ensures test assertions remain predictable and degradation logic can be tested explicitly.

### 2d. Health Monitoring (Phase 19)

All I/O Orbit packages now automatically register health checks with `@gravito/monitor`'s `HealthRegistry`.

**Health endpoint response:**

```json
GET /health

{
  "status": "degraded",
  "orbits": {
    "atlas": { "status": "unhealthy", "latency": null, "error": "Connection pool exhausted" },
    "plasma": { "status": "healthy", "latency": 2 },
    "signal": { "status": "healthy", "latency": 45 }
  }
}
```

**Shutdown handlers:**

Graceful shutdown is now registered automatically for `atlas`, `plasma`, `signal`, `stream`, and `beam`. The shutdown deadline is configurable per-Orbit.

**Before (manual health check registration):**

```typescript
// Previously you had to register checks manually — or skip them
```

**After (automatic, no action required):**

```typescript
// Health checks are registered when the Orbit boots
// Access via GET /health (handled by HealthController)
import { HealthController } from '@gravito/monitor'

const app = new Photon()
app.mount('/health', new HealthController(healthRegistry))
```

## Updating Your Code

### Step 1 — Update peerDependencies

In every package that depends on Gravito Orbits, update the `peerDependencies` version ranges:

```json
{
  "peerDependencies": {
    "@gravito/core": "^3.0.0",
    "@gravito/atlas": "^3.0.0",
    "@gravito/photon": "^2.0.0",
    "@gravito/resilience": "^2.0.0",
    "@gravito/signal": "^4.0.0",
    "@gravito/monitor": "^4.0.0",
    "@gravito/stream": "^3.0.0"
  }
}
```

Refer to the version table above for the full list of new major versions.

### Step 2 — Replace message string catches with typed checks

Search your codebase for patterns like:

```typescript
catch (e) {
  if (e.message === 'some orbit error string') { ... }
  if (e.message.includes('connection')) { ... }
}
```

Replace with typed `instanceof` + `.code` checks:

```typescript
import { DatabaseException } from '@gravito/atlas'
import { CircuitOpenException } from '@gravito/resilience'

catch (e) {
  if (e instanceof DatabaseException && e.code === 'db.connection_failed') { ... }
  if (e instanceof CircuitOpenException) { ... }
}
```

### Step 3 — Use `.code` for programmatic error handling

If you previously branched on `.message` strings in error handling logic, switch to `.code`:

```typescript
// Before
function handleError(e: unknown) {
  if (e instanceof Error && e.message === 'Unauthorized') {
    return 401
  }
  return 500
}

// After
import { GravitoException } from '@gravito/core'

function handleError(e: unknown) {
  if (e instanceof GravitoException) {
    return e.status // already the correct HTTP status
  }
  return 500
}
```

### Step 4 — (Optional) Use OrbitDegradationManager

If you currently have manual `try/catch` around `CircuitOpenException` to provide fallback values, consider migrating to `OrbitDegradationManager`:

```typescript
import { OrbitDegradationManager } from '@gravito/resilience'

const degradationMgr = new OrbitDegradationManager()

// Register fallback once at startup
degradationMgr.registerFallback('atlas', {
  fn: async () => await redisCache.get('products:fallback'),
  ttl: 30_000, // cache for 30 seconds
})

// Use in request handlers
async function getProducts() {
  const result = await degradationMgr.execute(
    'atlas',
    () => withResilience(() => atlas.query('SELECT * FROM products'), resiliencePolicy)
  )

  if (result.degraded) {
    logger.warn('Atlas unavailable — serving cached data')
  }

  return result.value
}
```

## FAQ

**Do I need to change my Satellite code?**

Only if you were catching Orbit errors by `.message` string comparison. Existing `instanceof` checks for `Error` still work (all Gravito exceptions extend `Error`). The new typed exception classes are additive — they do not remove existing error types.

**What about `atlas.transactionWithRetry`?**

It still works unchanged. Do NOT wrap it with `withRetry` or `withResilience` retry policy — `transactionWithRetry` already handles deadlock retries internally. Double-wrapping results in quadratic retry counts.

**Will the `/health` endpoint work automatically?**

Yes — all I/O Orbit packages register their health checks with `HealthRegistry` when they boot. Mount `HealthController` on `/health` in your application to expose the endpoint. No additional configuration is required for basic health reporting.

**What happens if I forget to register a fallback with OrbitDegradationManager?**

If `execute()` encounters a `CircuitOpenException` and no fallback is registered for that orbit name, the exception is re-thrown unchanged. Your existing error handling code will still work.

**Are there breaking changes to the Photon request/response API?**

No. `@gravito/photon` version bumps to 2.0.0 due to the underlying `@gravito/core` dependency upgrade, but the HTTP API surface (routing, middleware, request/response) is unchanged.
