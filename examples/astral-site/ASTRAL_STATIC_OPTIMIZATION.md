# Astral Document Staticization Optimization Analysis

## 1. Current State Assessment
Currently, `@gravito/astral` dynamically generates the OpenAPI specification at runtime inside `OrbitAstral.install()`. The Swagger UI HTML and `openapi.json` are served via dynamic endpoints (`GET /docs` and `GET /openapi.json`).

### Observed Workflow
1. At application boot `PlanetCore.boot()`, the `OrbitAstral` module is installed.
2. The OpenAPI spec is generated on the **first request** to `/openapi.json` by traversing all registered routes (`router.compile()`) and converting Zod schemas to JSON Schema.
3. The specification is then cached in memory for subsequent requests.

## 2. Identified Bottlenecks & Problems
While dynamic generation is beneficial during development, it has several drawbacks in a production or CD pipeline environment:
* **Initial Request Latency**: The first user visiting the documentation will experience a slower response time due to the on-the-fly compilation of routes and Zod to JSON Schema transformation overhead.
* **Memory Footprint**: The generation process, particularly `zod-to-json-schema`, consumes memory that is otherwise unnecessary for the actual API server routing.
* **Limited Hosting Options**: If a team only wants to host the API documentation (e.g., on GitHub Pages, Cloudflare Pages, S3), they currently need a running Node/Bun server. Truly static hosting is not supported out-of-the-box.
* **CDN Dependencies**: The Swagger HTML dynamically loads its JS and CSS purely through `unpkg.com` CDNs, which might be blocked in enterprise/offline environments or slow to load.

## 3. Optimization and Improvement Directions

### Proposed Solution A: Provide a Pre-compilation / Static Export API
We can introduce an API or CLI script (e.g., `OrbitAstral.exportStatic(dir)` or `astral-build`) to generate the `openapi.json` and `index.html` at build time.

* **Actionable Step**: Add a `generateStaticSite(outputDir: string)` utility method to `OrbitAstral`.
* **Execution**: A build script like `bun run scripts/build-docs.ts` would instantiate `OrbitAstral`, read the routes, and write the static files `dist/docs/index.html` and `dist/docs/openapi.json`.

### Proposed Solution B: Offline-Capable Swagger UI (Bundle Assets)
To avoid CDN dependencies and potential cross-origin latency, `astral` should offer offline capability.

* **Actionable Step**: Allow an option `serveStaticAssets: true` to bundle `swagger-ui-bundle.js` and CSS internally, or download them during the static generation build step.

### Proposed Solution C: "Pre-baked" Loading Mode for Production
For the actual running API server, if an `openapi.json` has already been generated by CI/CD, the server should simply stream that static JSON file rather than calling `router.compile()` and dynamically generating it.

* **Actionable Step**: Add a config option `specFilePath: string`. If this is provided, the server will read the file from disk (or serve statically) instead of executing `openApiGenerator.generateWithCache(...)`.

### Solution Comparison Matrix

| Solution | Pros | Cons | Use Case | Priority |
|----------|------|------|----------|----------|
| **A: Pre-compilation** | Zero initial latency, CDN-free, true static hosting (GitHub Pages/S3) | Requires build step, spec file sync overhead | CI/CD deployments, static documentation sites | **High** |
| **B: Offline Assets** | Enterprise-ready, no external CDN, offline-capable | Increased bundle size (+~500KB), maintenance burden | Enterprise/government environments, air-gapped networks | **Medium** |
| **C: Pre-baked Mode** | Minimal runtime overhead, fastest production startup | Requires pre-generated spec, more config complexity | Production API servers with pre-built docs | **High** |

## 4. Performance Expectations

| Metric | Current (Dynamic) | With Optimization | Improvement |
|--------|-------------------|-------------------|-------------|
| Initial `/docs` latency | 150-300ms | <10ms (static) | **95%+ reduction** |
| First request to `/openapi.json` | 200-400ms | <5ms (cached) | **98%+ reduction** |
| Memory footprint (astral module) | ~5-8 MB | ~0.5-1 MB | **85%+ reduction** |
| CDN dependency | Yes (unpkg.com) | Optional | **Zero hard dependency** |
| Static hosting support | No | Yes | **Enables GitHub Pages, S3, Netlify** |

## 5. Implementation Plan for Next Phase

### Phase 1: Core Infrastructure (Priority: High)
1. **Create static export utility** (`packages/astral/src/export-static.ts`)
   - Implement `generateStaticSite(config: { router, outputDir, baseUrl })` function
   - Handle Zod schema to JSON Schema conversion at build time
   - Generate `openapi.json` and `index.html` with embedded CSS/JS

2. **Modify OrbitAstral** (`packages/astral/src/orbit.ts`)
   - Add `exportStatic(outputDir: string)` public method
   - Support optional `specFilePath` config option for pre-baked mode (Solution C)

3. **Create build script** (`scripts/build-docs.ts`)
   - Demonstrate how to invoke `OrbitAstral.exportStatic()`
   - Show integration with CI/CD pipeline

### Phase 2: Example Integration (Priority: High)
1. **Update example** (`examples/astral-site/src/index.ts`)
   - Add conditional logic: if `process.env.BUILD_STATIC_DOCS === 'true'`, trigger static export instead of starting server
   - Call `exportStatic('./dist/docs')`

2. **Add build commands** (`examples/astral-site/package.json`)
   - `build:docs` → `BUILD_STATIC_DOCS=true bun src/index.ts`
   - `serve:docs` → existing dynamic server for development

### Phase 3: Asset Bundling (Priority: Medium)
1. **Implement offline mode** (`packages/astral/src/offline-assets.ts`)
   - Option: Bundle Swagger UI assets during `generateStaticSite()`
   - Option: Self-host swagger-ui via `/swagger-ui/` endpoint
   - Add config flag `bundleOfflineAssets: boolean`

### Phase 4: Testing & Documentation (Priority: Medium)
1. Add tests for static generation in `packages/astral/tests/`
2. Document usage in `docs/astral/static-export.md`
3. Update `CONTRIBUTING.md` with static docs generation workflow
