## 🚀 Bootstrap Lifecycle

The application follows a **4-phase initialization lifecycle**:

### 1. Configure
- Load configuration from `config/` directory
- Register Gravito Orbits (Atlas, Monolith)

### 2. Boot Core
- Initialize `PlanetCore` with PhotonAdapter
- Register global error handlers

### 3. Register Providers
- `DatabaseProvider` - Database schema initialization
- `MiddlewareProvider` - Security headers, body limit
- `RouteProvider` - Application routes

### 4. Bootstrap
- Boot all registered providers
- Initialize database tables
- Register middleware
- Define routes

## 🏗️ Architecture Patterns

### MVC Pattern
- **Models**: Data representation and database interaction (`Models/`)
- **Views**: API responses (JSON)
- **Controllers**: Request handling and response formatting (`Http/Controllers/`)

### Service Provider Pattern
All infrastructure concerns are encapsulated in Service Providers:
- Modular initialization
- Dependency injection ready
- Clear separation of concerns

### Repository Pattern (Optional)
For complex data access logic, use the `Repositories/` layer.

### Service Layer (Optional)
For complex business logic, use the `Services/` layer.

## 📝 Key Features

### 1. Configuration Management
All configuration is centralized in `config/`:
- Environment-based settings
- Type-safe configuration objects
- Easy to test and override

### 2. Security by Default
- Content Security Policy (CSP)
- HTTP Strict Transport Security (HSTS)
- Request body size limits
- Configurable via environment variables

### 3. Database Management
- Schema initialization via `DatabaseProvider`
- Atlas ORM with decorators
- Migration and seeder support

### 4. Route Organization
- Centralized route definitions in `routes.ts`
- Controller-based routing
- Form Request validation

## 🧪 API Endpoints

### Products
- `GET /` - Welcome message
- `GET /products` - List all products
- `GET /products/:id` - Get product by ID
- `POST /products` - Create new product (validated)

## 📚 Best Practices

1. **Keep Controllers Thin**: Move business logic to Services
2. **Use Form Requests**: Validate input with dedicated classes
3. **Leverage Providers**: Organize initialization logic
4. **Follow Naming Conventions**: PascalCase for directories and classes
5. **Separate Concerns**: Config → Providers → Routes → Controllers
