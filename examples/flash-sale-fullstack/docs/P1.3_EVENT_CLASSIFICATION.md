## 事件分類概述

在 Flash Sale 系統中，有 **18 種核心事件類型**，分為 **6 大類別**，共 **4 個優先級**。

```
快取事件系統
├─ 商品事件 (3 個)
├─ 庫存事件 (3 個)
├─ 價格事件 (2 個)
├─ 促銷事件 (3 個)
├─ 訂單事件 (3 個)
└─ 系統事件 (4 個)
```

---

## 事件類型詳解

### 1. 商品事件 (Product Events)

#### 1.1 PRODUCT_UPDATED - 商品更新

**觸發條件**：
- 商品名稱、描述、圖片等信息更新
- 商品分類更改
- 商品屬性變化

**失效模式**：
```
product:{productId}           // 特定商品快取
product:*:details             // 所有商品詳情快取
product:{category}:*          // 分類快取
```

**優先級**：HIGH (< 50ms)

**元數據示例**：
```typescript
{
  productId: "SKU123",
  field: "description",
  oldValue: "...",
  newValue: "..."
}
```

---

#### 1.2 PRODUCT_DELETED - 商品刪除

**觸發條件**：
- 商品下架或永久刪除

**失效模式**：
```
product:{productId}           // 特定商品快取
product:*:list                // 商品列表快取
```

**優先級**：LOW (< 500ms)

**備註**：刪除操作不緊急，可延遲處理

---

#### 1.3 PRODUCT_BATCH_UPDATE - 商品批量更新

**觸發條件**：
- 批量導入商品
- 批量更新商品屬性
- 定時任務更新

**失效模式**：
```
product:*                     // 清空所有商品快取
product:*:list
product:*:details
```

**優先級**：NORMAL (< 200ms)

**元數據示例**：
```typescript
{
  batchId: "batch_123",
  count: 1000,
  fields: ["price", "inventory"]
}
```

---

### 2. 庫存事件 (Inventory Events)

#### 2.1 INVENTORY_CHANGED - 庫存變化

**觸發條件**：
- 庫存增加或減少
- 庫存調整（例如退貨、損耗）

**失效模式**：
```
inventory:{productId}         // 特定產品庫存
inventory:*:count             // 所有庫存計數
inventory:*:available         // 可用庫存快取
```

**優先級**：HIGH (< 50ms)

**元數據示例**：
```typescript
{
  productId: "SKU123",
  delta: -5,                  // 庫存變化數量
  reason: "sale",             // 原因：sale, refund, adjustment
  beforeCount: 100,
  afterCount: 95
}
```

---

#### 2.2 INVENTORY_RESERVED - 庫存預留

**觸發條件**：
- 訂單確認時保留庫存
- 下單時鎖定庫存

**失效模式**：
```
inventory:{productId}:reserved
inventory:*:available         // 可用庫存減少
```

**優先級**：CRITICAL (立即 < 1ms)

**備註**：最高優先級，直接影響秒殺邏輯

---

#### 2.3 INVENTORY_RELEASED - 庫存釋放

**觸發條件**：
- 訂單取消時釋放庫存
- 預留超時釋放

**失效模式**：
```
inventory:{productId}:reserved
inventory:*:available         // 可用庫存增加
```

**優先級**：CRITICAL (立即 < 1ms)

---

### 3. 價格事件 (Pricing Events)

#### 3.1 PRICE_CHANGED - 價格變化

**觸發條件**：
- 基礎價格調整
- 折扣率變化
- 動態定價更新

**失效模式**：
```
price:{productId}             // 特定商品價格
price:*:current               // 當前價格快取
price:*:tier                  // 價格層級快取
```

**優先級**：HIGH (< 50ms)

**元數據示例**：
```typescript
{
  productId: "SKU123",
  oldPrice: 99.99,
  newPrice: 89.99,
  changeType: "discount"      // discount, increase, tier
}
```

---

#### 3.2 PRICE_TIER_UPDATED - 價格層級更新

**觸發條件**：
- 調整批量購買價格層級
- 會員等級價格變化

**失效模式**：
```
price:*:tier
price:*:member                // 會員價格
```

**優先級**：HIGH (< 50ms)

---

### 4. 促銷事件 (Promotion Events)

#### 4.1 PROMOTION_STARTED - 促銷開始

**觸發條件**：
- 新的促銷活動開始
- Flash Sale 活動開始

**失效模式**：
```
promotion:active:*            // 活動促銷快取
product:*:promotion           // 商品促銷信息
```

**優先級**：HIGH (< 50ms)

**元數據示例**：
```typescript
{
  promotionId: "promo_123",
  type: "flash_sale",
  productIds: ["SKU1", "SKU2", ...],
  startTime: 1707564000000,
  endTime: 1707567600000
}
```

---

#### 4.2 PROMOTION_ENDED - 促銷結束

**觸發條件**：
- 促銷活動結束
- Flash Sale 活動結束

**失效模式**：
```
promotion:active:*
product:*:promotion
```

**優先級**：HIGH (< 50ms)

---

#### 4.3 PROMOTION_UPDATED - 促銷更新

**觸發條件**：
- 調整促銷折扣率
- 修改參與商品列表
- 修改活動時間

**失效模式**：
```
promotion:{promotionId}
product:*:promotion
```

**優先級**：NORMAL (< 200ms)

---

### 5. 訂單事件 (Order Events)

#### 5.1 ORDER_PLACED - 訂單下達

**觸發條件**：
- 用戶成功下單

**失效模式**：
```
order:*:recent                // 最近訂單快取
user:{userId}:orders          // 用戶訂單列表
```

**優先級**：NORMAL (< 200ms)

**元數據示例**：
```typescript
{
  orderId: "ORD123456",
  userId: "user_789",
  items: [{productId: "SKU1", quantity: 2}, ...],
  totalAmount: 199.98
}
```

---

#### 5.2 ORDER_COMPLETED - 訂單完成

**觸發條件**：
- 訂單已發貨
- 訂單已交付

**失效模式**：
```
order:*:recent
order:{orderId}
inventory:*:available         // 庫存最終確認
```

**優先級**：CRITICAL (< 1ms)

**備註**：最高優先級，確保庫存最終一致性

---

#### 5.3 ORDER_CANCELLED - 訂單取消

**觸發條件**：
- 用戶取消訂單
- 支付失敗
- 庫存不足無法履行

**失效模式**：
```
order:{orderId}
user:{userId}:orders
inventory:*:available
```

**優先級**：LOW (< 500ms)

---

### 6. 系統事件 (System Events)

#### 6.1 BATCH_INVALIDATION - 批量失效

**觸發條件**：
- 批量失效請求
- 模式批量清理

**失效模式**：由批量請求指定

**優先級**：NORMAL (< 200ms)

---

#### 6.2 SYSTEM_CACHE_FLUSH - 系統快取清空

**觸發條件**：
- 系統初始化
- 緊急快取清理
- 定期維護

**失效模式**：
```
*                             // 清空所有快取
```

**優先級**：LOW (< 500ms)

---

#### 6.3 CACHE_WARMUP_TRIGGERED - 快取預熱觸發

**觸發條件**：
- 定期預熱任務
- 熱度更新觸發預熱

**失效模式**：無（用於預熱，不失效）

**優先級**：LOW (< 500ms)

## 優先級分配策略

### 優先級定義

| 優先級 | 處理延遲 | 聚合窗口 | 聚合限制 | 使用場景 |
|--------|---------|---------|---------|---------|
| **CRITICAL** | < 1ms | 0ms | 1 | 庫存、訂單 |
| **HIGH** | < 50ms | 50ms | 10 | 商品、價格、促銷 |
| **NORMAL** | < 200ms | 200ms | 50 | 批量、訂單、系統 |
| **LOW** | < 500ms | 500ms | 100 | 刪除、清理、預熱 |

### 優先級分配規則

**CRITICAL (立即處理)**：
- 直接影響交易的事件
- 需要實時性的業務邏輯
- 訂單和庫存相關

**HIGH (快速處理)**：
- 影響用戶體驗的事件
- 商品、價格、促銷信息變化
- 需要在 50ms 內生效

**NORMAL (標準處理)**：
- 批量操作
- 非立即影響的業務
- 可以聚合處理的事件

**LOW (後台處理)**：
- 刪除、清理操作
- 維護類任務
- 預熱和預設性操作

## 事件源標識

事件源幫助追蹤事件來自何處，便於監控和故障排查。

| 源標識 | 說明 | 示例事件 |
|--------|------|---------|
| `product_service` | 商品服務 | PRODUCT_UPDATED |
| `inventory_service` | 庫存服務 | INVENTORY_CHANGED |
| `price_service` | 定價服務 | PRICE_CHANGED |
| `order_service` | 訂單服務 | ORDER_PLACED |
| `promotion_service` | 促銷服務 | PROMOTION_STARTED |
| `system` | 系統內部 | SYSTEM_CACHE_FLUSH |
| `api` | 外部 API | BATCH_INVALIDATION |
| `scheduler` | 定時任務 | CACHE_WARMUP_TRIGGERED |

## 模式生成規則

### 通用模式格式

```
{entity}:{id}[:{attribute}]
```

例如：
- `product:SKU123` - 特定商品
- `inventory:*:count` - 所有庫存計數
- `price:tier:*` - 所有價格層級

### 模式匹配規則

| 模式 | 匹配範圍 | 示例 |
|------|---------|------|
| `product:123` | 精確 | 商品 123 |
| `product:*` | 通配符 | 所有商品 |
| `product:*:details` | 前綴+後綴 | 所有商品詳情 |
| `*` | 全局 | 整個快取 |

### 模式生成邏輯

```typescript
PRODUCT_UPDATED:
  → product:{productId}
  → product:*:details

INVENTORY_CHANGED:
  → inventory:{productId}
  → inventory:*:count

PRICE_CHANGED:
  → price:{productId}
  → price:*:current

PROMOTION_STARTED:
  → promotion:active:*
  → product:*:promotion
  → product:{productId}:promotion

BATCH_INVALIDATION:
  → [custom patterns from metadata]
```

## 優先級升級機制

### 自動升級規則

當事件等待時間超過其優先級的預期延遲時，自動升級到更高優先級。

**升級時間表**：

| 原優先級 | 升級條件 | 升級至 |
|---------|---------|--------|
| LOW | 等待 > 200ms | NORMAL |
| NORMAL | 等待 > 100ms | HIGH |
| HIGH | 等待 > 50ms | CRITICAL |

**範例**：
- 一個 LOW 優先級事件進隊列
- 等待 150ms 時：仍為 LOW
- 等待 250ms 時：自動升級為 NORMAL
- 等待 350ms 時：自動升級為 HIGH
- 等待 450ms 時：自動升級為 CRITICAL

### 升級好處

1. **公平性**：防止低優先級事件無限等待
2. **適應性**：自動應對負載突增
3. **可預測性**：保證最大延遲

## 最佳實踐

### 事件發佈

1. **使用適當優先級**：根據業務影響選擇優先級
2. **提供元數據**：幫助系統作出更好的決策
3. **避免嵌套失效**：不要在事件處理中發佈事件

### 事件消費

1. **冪等性**：事件應該可以安全重放
2. **快速處理**：避免在事件處理中進行長時間操作
3. **錯誤處理**：妥善處理失效失敗的情況

### 監控和告警

1. **關鍵事件延遲**：HIGH/CRITICAL 事件延遲 > 100ms
2. **隊列堆積**：隊列深度 > 1000
3. **失效失敗率**：失敗率 > 1%
