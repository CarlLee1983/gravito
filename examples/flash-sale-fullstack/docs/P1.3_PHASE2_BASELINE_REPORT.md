## 問題發現

### 1. EventAggregator.submit() 性能 ⚠️

**現象**：
- 2000 次提交耗時 ~15 秒（133 ops/sec）
- 遠低於預期的 1000+ ops/sec
- 背壓激活，隊列深度達到 539

**根本原因**（初步分析）：
- 可能的原因：
  1. 背壓管理器實施過於嚴格
  2. 去重操作性能不佳
  3. 隊列操作複雜度未優化
  4. 事件對象創建開銷

**改進策略**：
1. 分析 BackpressureManager 的 applyBackpressure() 實現
2. 優化 EventDeduplicator 的去重算法
3. 考慮使用更高效的隊列實現
4. 減少事件對象的深複製

### 2. 隊列背壓激活

**現象**：
- 在 1000 個事件時，背壓已激活
- 最大隊列深度 539

**影響**：
- 可能導致事件被拒絕
- 影響系統吞吐量

## 優化方案（Phase 2 Phase 2）

### Phase 2.1 - 快速路徑優化（1h）

1. **背壓算法調整**
   - 增加初始背壓閾值
   - 實施漸進式背壓升級
   - 優化狀態轉換邏輯

2. **隊列操作優化**
   - 使用循環緩衝區替代鏈表
   - 減少內存分配
   - 批量操作支持

3. **去重優化**
   - 實施布隆過濾器快速路徑
   - 優化模式匹配算法
   - 減少字符串複製

### Phase 2.2 - 內存優化（1h）

1. **對象池模式**
   - 重用 CacheEvent 對象
   - 減少 GC 壓力
   - 提升內存局部性

2. **批處理優化**
   - 批量提交事件
   - 減少同步開銷
   - 改善隊列吞吐量
