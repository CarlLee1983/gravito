# P2.2.1 - 多區域架構設計

## 概述

本文檔介紹 Flash Sale 系統的全球多區域部署架構設計，包括區域規劃、複製策略、故障轉移機制和地域路由。

**設計目標**：
- ✅ 支持 4 個主要地理區域
- ✅ 實現高可用性（99.99% SLA）
- ✅ 自動故障轉移（RTO < 1 分鐘）
- ✅ 數據一致性保障（RPO < 1 秒）
- ✅ 全球流量優化（延遲 < 100ms）

## 2. 複製策略

### 2.1 單主複製（Single-Master Replication）

**架構圖**：
```
┌─────────────────────────────────────────────┐
│           US-East (主區域)                   │
│  ┌─────────────────────────────────────┐   │
│  │  Master Database                    │   │
│  │  ├─ Orders (分片 0-7)               │   │
│  │  ├─ Products (分片 0-7)             │   │
│  │  └─ Inventory (分片 0-7)            │   │
│  └─────────────────────────────────────┘   │
│           ↓ 非同步複製 (async)              │
│           ↓ 半同步複製 (semi-sync)         │
├─────────────────────────────────────────────┤
│ US-West     │  EU-West    │  AP-Southeast  │
│ 備份數據庫  │  只讀副本   │  只讀副本      │
│ 完整數據    │  完整數據   │  完整數據      │
│ (~100ms lag)│ (~200ms lag)│ (~300ms lag)   │
└─────────────────────────────────────────────┘
```

**複製流程**：
```
寫操作：
1. 應用發送寫請求到 US-East
2. US-East 主節點立即確認
3. 非同步複製到其他 3 個區域
4. 應用無需等待複製完成

讀操作：
1. 應用優先讀本地區域
2. 若本地無最新數據，讀主區域
3. 最終一致性（通常 < 1 秒）
```

**配置參數**：
```typescript
const replicationStrategy: ReplicationStrategy = {
  type: 'single-master',
  primaryRegion: 'us-east-1',
  secondaryRegions: ['us-west-2', 'eu-west-1', 'ap-southeast-1'],
  replicationMode: 'async',      // 非同步複製
  conflictResolution: 'master-wins' // 衝突解決
}
```

**優點**：
- ✅ 簡單易懂
- ✅ 衝突解決簡單
- ✅ 一致性強
- ✅ 故障轉移快速

**缺點**：
- ❌ 主區域故障時有短暫停機
- ❌ 多數寫操作都需訪問主區域

### 2.2 複製模式選擇

| 模式 | 延遲 | 一致性 | 使用場景 |
|------|------|--------|---------|
| **async** | 低 | 最終一致 | 秒殺（可容忍延遲） |
| **semi-sync** | 中 | 準強一致 | 訂單（需要一致性） |
| **sync** | 高 | 強一致 | 支付（必須一致） |

**推薦方案**：
```typescript
// 秒殺商品（高併發，可容忍延遲）
replicationMode: 'async'

// 訂單系統（需要一致性）
replicationMode: 'semi-sync'

// 支付交易（必須一致）
replicationMode: 'sync'
```

## 3. 故障轉移機制

### 3.1 故障轉移流程

```
故障檢測 (5 sec) → 決策 (10 sec) → 切換 (30 sec) → 驗證 (15 sec)
                                     Total: ~60 sec (1 分鐘內)
```

**詳細步驟**：

```
┌─────────────────────────────────────────────┐
│  1. 故障檢測 (5 秒)                         │
│  ├─ 心跳檢測失敗                           │
│  ├─ 錯誤率 > 5%                            │
│  ├─ 延遲 > 500ms                          │
│  └─ 觀察時間: 3 次連續失敗                │
├─────────────────────────────────────────────┤
│  2. 轉移決策 (10 秒)                       │
│  ├─ 選擇最佳備用區域                      │
│  │  └─ 健康狀態最佳                      │
│  ├─ 驗證備用區域可用性                    │
│  └─ 確認副本數據完整                      │
├─────────────────────────────────────────────┤
│  3. 流量切換 (30 秒)                       │
│  ├─ 更新 DNS (TTL=60s)                    │
│  ├─ 更新負載均衡器                        │
│  ├─ 更新應用配置                          │
│  ├─ 切換 VIP (虛擬 IP)                    │
│  └─ 逐步切換流量 (Gradual Shift)         │
├─────────────────────────────────────────────┤
│  4. 驗證 (15 秒)                           │
│  ├─ 檢查新主區域狀態                      │
│  ├─ 驗證數據一致性                        │
│  ├─ 監控錯誤率                            │
│  └─ 確認用戶請求正常                      │
└─────────────────────────────────────────────┘
```

### 3.2 故障轉移策略配置

```typescript
const failoverPolicies: FailoverPolicy[] = [
  {
    regionId: 'us-east-1',
    priority: 1,
    threshold: {
      errorRate: 5,           // > 5% 錯誤率
      latency: 500,          // > 500ms 延遲
      unavailableTime: 30    // > 30 秒不可用
    },
    action: 'automatic',     // 自動故障轉移
    recoveryTime: 60         // 恢復時間: 60 秒
  },
  {
    regionId: 'us-west-2',
    priority: 2,
    threshold: {
      errorRate: 10,
      latency: 1000,
      unavailableTime: 60
    },
    action: 'automatic',
    recoveryTime: 120
  },
  // ... 其他區域
]
```

### 3.3 故障轉移決策樹

```
US-East 故障?
  ├─ 健康檢查失敗 (3 次)
  │  └─ 選擇最佳備用區域
  │     ├─ US-West (60ms 延遲, 優先)
  │     ├─ EU-West (120ms 延遲)
  │     └─ AP-Southeast (150ms 延遲)
  │
  ├─ 部分故障 (Error Rate 5-10%)
  │  └─ 限流並重試，不轉移
  │
  └─ 故障恢復
     └─ 自動切回主區域
```

### 4.2 地域選擇算法

```typescript
selectRegionByGeo(userIP: string, countryCode?: string): string {
  // 優先級 1: 精確 IP 匹配
  for (const rule of routingRules) {
    if (rule.enabled && matchIP(userIP, rule.pattern)) {
      return rule.targetRegion
    }
  }

  // 優先級 2: 國家代碼匹配
  if (countryCode) {
    const regionId = countryToRegion[countryCode]
    if (regionId) return regionId
  }

  // 優先級 3: 返回主區域
  return 'us-east-1'
}
```

## 5. 健康檢查

### 5.1 健康檢查策略

```typescript
interface RegionHealth {
  regionId: string
  status: 'healthy' | 'degraded' | 'unhealthy'
  lastCheck: Date
  errorRate: number      // %
  avgLatency: number     // ms
  activeConnections: number
}
```

**檢查間隔**：
- 健康區域: 30 秒一次
- 降級區域: 10 秒一次
- 故障區域: 5 秒一次

**健康判定標準**：
```
✅ 健康:
  ├─ 錯誤率 < 1%
  ├─ P99 延遲 < 200ms
  └─ 可用性 > 99.9%

⚠️ 降級:
  ├─ 錯誤率 1-5%
  ├─ P99 延遲 200-500ms
  └─ 可用性 99-99.9%

❌ 故障:
  ├─ 錯誤率 > 5%
  ├─ P99 延遲 > 500ms
  └─ 不可連接
```

### 5.2 健康檢查實現

```typescript
async performHealthCheck(regionId: string): Promise<RegionHealth> {
  const config = getRegionConfig(regionId)

  // 1. TCP 連接測試
  const tcpSuccess = await checkTCPConnection(config.endpoint, config.port)

  // 2. HTTP 健康端點測試
  const httpOk = await checkHTTPHealth(`${config.endpoint}/health`)

  // 3. 查詢響應時間測試
  const latency = await measureQueryLatency(regionId)

  // 4. 複製延遲測試
  const replicationLag = await measureReplicationLag(regionId)

  return {
    regionId,
    status: calculateStatus(tcpSuccess, httpOk, latency),
    lastCheck: new Date(),
    errorRate: calculateErrorRate(regionId),
    avgLatency: latency,
    activeConnections: getActiveConnections(regionId)
  }
}
```

## 6. 多區域一致性保障

### 6.1 數據一致性模型

**最終一致性** (秒殺商品)：
```
時間線:
T+0ms   : 主區域寫入完成，應用返回成功
T+100ms : US-West 副本更新
T+200ms : EU-West 副本更新
T+300ms : AP-Southeast 副本更新

用戶體驗: 即時返回，數據最終一致
```

**準強一致性** (訂單系統)：
```
時間線:
T+0ms   : 主區域寫入
T+10ms  : 等待至少 1 個副本確認 (semi-sync)
T+20ms  : 應用返回成功
T+100ms : 所有副本最終一致

用戶體驗: 短暫延遲，強一致性保障
```

### 6.2 衝突解決策略

| 衝突類型 | 解決方案 | 適用場景 |
|---------|--------|---------|
| 並發寫 | Last-Write-Wins | 產品信息 |
| 庫存扣減 | Vector Clock | 庫存系統 |
| 價格更新 | Master-Wins | 價格管理 |
| 用戶信息 | Manual Merge | 賬戶信息 |

```
US 用戶    → US 區域 (70%)

```

## 9. 災難恢復計畫

### 9.1 故障恢復流程

**場景 1: 單個區域故障**
```
故障發生 → 自動轉移 (1 min) → 運維驗證 (5 min) → 修復故障 → 恢復
```

**場景 2: 多個區域故障**
```
故障發生 → 切換到健康區域 → 通知管理層 → 調查根本原因 → 修復
```

**場景 3: 全局故障**
```
故障發生 → 激活災難恢復計畫 → 從備份恢復 → 數據驗證 → 恢復服務
```

### 9.2 備份策略

```
備份頻率:
├─ 實時複製: 所有區域
├─ 快照備份: 每小時
├─ 冷備: 地理隔離位置

備份保留:
├─ 實時副本: 無限期
├─ 小時快照: 7 天
├─ 日常備份: 30 天
└─ 月度備份: 1 年
```
