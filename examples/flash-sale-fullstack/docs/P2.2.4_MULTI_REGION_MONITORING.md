# P2.2.4 - 多區域監控和告警

## 概述

多區域監控和告警系統是 Flash Sale 超大規模架構的運維支柱，提供**跨區域統一監控**、**智能告警管理**和**自動故障恢復**。該系統通過實時指標收集、告警規則評估和自動修復，確保系統的高可用性和穩定性。

**關鍵指標：**
- 告警響應時間：< 10 秒
- 指標收集延遲：< 1 秒
- 自動修復成功率：> 90%
- 誤報率：< 5%

## 架構設計

### 系統組件

```
┌──────────────────────────────────────────────────────┐
│    RegionalMonitoringSystem (多區域監控中樞)          │
├──────────────────────────────────────────────────────┤
│ ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│ │ Metrics      │  │ Alert Rules  │  │ Health       │ │
│ │ Collector    │  │ Manager      │  │ Checker      │ │
│ └──────────────┘  └──────────────┘  └──────────────┘ │
├──────────────────────────────────────────────────────┤
│  US-East        EU-West        AP-Southeast         │
│  區域 1          區域 2          區域 3               │
└──────────────────────────────────────────────────────┘
        ↓
  自動修復引擎 (Auto-Remediation)
  ├─ 水平擴展 (Scale Out)
  ├─ 清理快取 (Clear Cache)
  └─ 故障轉移 (Failover)
```

### 監控指標體系

```
Metrics (指標)
├─ Performance (性能指標)
│  ├─ Latency (延遲)
│  │  ├─ P50: 中位延遲
│  │  ├─ P95: 95 百分位延遲
│  │  ├─ P99: 99 百分位延遲 ⭐ (關鍵)
│  │  └─ P999: 99.9 百分位延遲
│  └─ Throughput (吞吐量): req/sec
├─ Reliability (可靠性指標)
│  ├─ Error Rate: %
│  └─ Success Rate: %
├─ Resource (資源指標)
│  ├─ CPU Usage: %
│  ├─ Memory Usage: %
│  └─ Disk Usage: %
└─ Availability (可用性指標)
   ├─ Cache Hit Rate: %
   └─ Active Connections: count
```

### 2. 告警規則管理

```typescript
// 定義告警規則
interface AlertRule {
  ruleId: string
  name: string
  description: string
  enabled: boolean
  condition: {
    metric: string           // 監控指標名
    operator: '>' | '<' | '=' | '!='
    threshold: number        // 閾值
    duration: number         // 持續時間 (秒)
  }
  severity: 'critical' | 'warning' | 'info'
  actions: AlertAction[]     // 執行動作
  triggerCount: number       // 觸發次數
}

// 創建告警規則
const rule: AlertRule = {
  ruleId: 'high-latency',
  name: 'High Latency Alert',
  description: 'P99 延遲超過 200ms',
  enabled: true,
  condition: {
    metric: 'latency.p99',
    operator: '>',
    threshold: 200,
    duration: 60
  },
  severity: 'warning',
  actions: [
    { type: 'slack', target: '#alerts' },
    { type: 'email', target: 'ops@company.com' }
  ],
  triggerCount: 0
}

monitoring.createAlertRule(rule)
```

### 3. 告警評估和觸發

```
指標收集 → 規則評估 → 判斷是否觸發
                    ↓
              觸發告警 → 執行動作 → 自動修復
                    ↓
              發送通知 → 記錄事件
```

**評估邏輯：**
```typescript
// 檢查條件是否滿足
if (metric[rule.condition.metric] > rule.condition.threshold) {
  // 1. 觸發告警
  triggerAlert(rule, regionId, metricValue)

  // 2. 執行告警動作 (郵件、Slack、PagerDuty 等)
  executeAlertActions(rule, alert)

  // 3. 嘗試自動修復 (如果啟用)
  if (enableAutoRemediation) {
    attemptAutoRemediation(regionId, rule, alert)
  }
}
```

```typescript
// 健康狀態判斷標準
interface HealthStatus {

Healthy: 所有指標正常

Unhealthy: 3+ 個指標異常
```

### 5. 自動修復機制

```typescript
// 根據指標類型進行自動修復

if (metric === 'cpuUsage' && value > threshold) {
  // 觸發水平擴展
  emit('remediation:scale-out', { regionId, alert })
}

if (metric === 'memoryUsage' && value > threshold) {
  // 清理快取

}

if (metric === 'errorRate' && value > threshold) {
  // 觸發故障轉移
  emit('remediation:failover', { regionId, alert })
}
```

## 告警級別和動作

### Critical (嚴重)
```
觸發條件：
├─ 錯誤率 > 2%
├─ P99 延遲 > 300ms
├─ CPU 使用率 > 95%
└─ 可用性 < 99%

執行動作：
├─ PagerDuty 通知 (立即)
├─ Slack @critical-team
├─ Email ops-team
└─ 自動修復：故障轉移
```

### Warning (警告)
```
觸發條件：
├─ 錯誤率 0.5-2%
├─ P99 延遲 200-300ms
├─ CPU 使用率 80-95%
└─ 快取命中率 < 85%

執行動作：
├─ Slack #alerts
├─ Email on-call
└─ 自動修復：水平擴展或清快取
```

### Info (信息)
```
觸發條件：
├─ 錯誤率 < 0.5%
├─ P99 延遲 < 200ms
├─ 使用率正常變動

執行動作：
├─ 日誌記錄
└─ Dashboard 儀表板更新
```

## 故障排除

### 問題：告警誤報過多

**症狀：** 告警頻繁觸發，但系統正常
**原因：**
- 閾值設置過低
- 持續時間過短
- 指標波動性大

**解決方案：**
```typescript
// 增加持續時間
condition.duration = 60  // 從 30 秒改為 60 秒

// 提高閾值
condition.threshold = 2  // 從 1% 改為 2%

// 使用百分位指標
// 用 P99 代替平均值（更穩定）
```

### 問題：無法自動修復

**症狀：** 自動修復失敗，告警無法解決
**原因：**
- 修復操作權限不足
- 依賴服務不可用
- 修復規則不匹配

**解決方案：**
```typescript
// 1. 檢查權限
verifyAutoScalingPermissions()

// 2. 驗證依賴
checkDependencies(['auto-scaling-api', 'cache-service'])

// 3. 添加回退機制
try {
  attemptAutoRemediation()
} catch (e) {
  manualAlert('Auto-remediation failed: ' + e)
}
```

### 問題：指標數據丟失

**症狀：** 監控圖表有數據缺口
**原因：**
- 收集間隔錯誤
- 存儲限制
- 區域連接問題

**解決方案：**
```typescript
// 驗證收集間隔
console.assert(config.collectInterval === 30000)

// 監控存儲使用
if (storageUsage > maxSize * 0.8) {
  alert('Storage nearly full')
}

// 檢查區域連接
for (const region of regions) {
  if (!region.isConnected()) {
    reconnectRegion(region)
  }
}
```

