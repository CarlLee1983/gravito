# P2.2.2 - 跨區域應用部署

## 概述

跨區域應用部署系統是 Flash Sale 超大規模架構的核心模組，負責協調多個地域區域的應用版本更新和故障恢復。該系統實現了**零停機部署**、**自動故障轉移**和**完整回滾機制**。

**關鍵指標：**
- 部署時間：5 分鐘/區域（3 個區域共 15 分鐘）
- 故障轉移時間：< 1 分鐘
- 版本同步延遲：< 10 秒

## 架構設計

### 系統組件

```
┌─────────────────────────────────────────────────────────────┐
│          CrossRegionDeploymentManager (主控制器)            │
├─────────────────────────────────────────────────────────────┤
│ • 版本管理 (DeploymentVersion)                              │
│ • 部署計劃 (RegionDeploymentPlan)                           │
│ • 區域狀態 (RegionDeploymentStatus)                         │
│ • 同步狀態 (SyncState)                                      │
│ • 依賴關係 (DeploymentDependency)                           │
├─────────────────────────────────────────────────────────────┤
│  區域 1        區域 2        區域 3        區域 4            │
│ (US-East)    (EU-West)   (AP-Southeast)  (US-West)         │
└─────────────────────────────────────────────────────────────┘
```

### 核心介面

#### 1. **DeploymentVersion** - 應用版本
```typescript
interface DeploymentVersion {
  versionId: string              // 版本標識符
  applicationId: string          // 應用 ID
  semver: string                 // 語義版本 (e.g., "1.2.3")
  deployedAt: Date              // 部署時間
  deployedBy: string            // 部署人員/系統
  checksum: string              // 部署包校驗和 (SHA256)
  features: string[]            // 功能列表
  rollbackable: boolean          // 是否可回滾
  status: 'pending'|'active'|'deprecated'|'failed'  // 版本狀態
}
```

#### 2. **RegionDeploymentPlan** - 部署計劃
```typescript
interface RegionDeploymentPlan {
  planId: string                 // 計劃 ID
  versionId: string              // 目標版本
  targetRegions: string[]        // 目標區域列表
  deploymentOrder: string[]      // 部署順序
  deploymentStrategy: 'canary'|'rolling'|'blue-green'
  rollbackOnFailure: boolean     // 失敗時回滾
  maxConcurrentRegions: number   // 最大並發區域數 (2)
  deploymentStartTime: Date
  estimatedCompletionTime: Date
}
```

#### 3. **RegionDeploymentStatus** - 部署狀態
```typescript
interface RegionDeploymentStatus {
  regionId: string               // 區域 ID
  versionId: string              // 部署版本
  deploymentPlanId: string       // 所屬計劃
  status: 'pending'|'in-progress'|'completed'|'failed'|'rolled-back'
  progress: number               // 進度 0-100%
  startedAt?: Date
  completedAt?: Date
  errorMessage?: string
  healthCheck: {
    isHealthy: boolean           // 健康狀態
    errorRate: number            // 錯誤率 (%)
    avgLatency: number           // 平均延遲 (ms)
    checkedAt: Date
  }
}
```

#### 4. **SyncState** - 同步狀態
```typescript
interface SyncState {
  regionId: string               // 區域 ID
  versionId: string              // 同步版本
  lastSyncTime: Date             // 最後同步時間
  isSynced: boolean              // 是否已同步
  pendingChanges: number         // 待同步變更數
  syncStatus: 'idle'|'syncing'|'out-of-sync'
}
```

## 部署流程

### 完整部署生命週期

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 版本註冊 (registerVersion)                                │
│    └─ 驗證版本完整性、計算校驗和                             │
├─────────────────────────────────────────────────────────────┤
│ 2. 創建部署計劃 (createDeploymentPlan)                       │
│    └─ 確定目標區域、計算部署順序                             │
├─────────────────────────────────────────────────────────────┤
│ 3. 執行部署 (executeDeploymentPlan)                          │
│    ├─ 3.1 驗證前置條件 (validateDeploymentPrerequisites)    │
│    ├─ 3.2 按順序部署到各區域                                │
│    │   ├─ 停止舊版本 (stopPreviousVersion)                  │
│    │   ├─ 部署新版本 (deployNewVersion)                     │
│    │   ├─ 健康檢查 (performHealthCheck)                     │
│    │   ├─ 驗證版本 (verifyVersionDeployment)                │
│    │   └─ 同步依賴區域 (syncDependentRegions)               │
│    └─ 3.3 驗證整體部署 (verifyOverallDeployment)            │
├─────────────────────────────────────────────────────────────┤
│ 4. 故障恢復 (rollbackDeployment)                             │
│    └─ 按反向順序回滾各區域                                   │
└─────────────────────────────────────────────────────────────┘
```

### 部署順序算法

區域優先級排序 (US-East 最高):
1. **us-east-1** (主區域, 優先級 0)
2. **eu-west-1** (優先級 1)
3. **ap-southeast-1** (優先級 2)
4. **us-west-2** (優先級 3)

### 單區域部署步驟 (5 分鐘)

```
時間    步驟                   說明
─────────────────────────────────────────────────────────
0:00   停止舊版本 (1:40)     停止現有服務，保留備份
1:40   部署新版本 (2:30)     複製新版本到區域
4:10   健康檢查 (0:30)       驗證新版本可用性
4:40   驗證版本 (0:50)       校驗版本完整性
5:30   同步區域 (1:00)       與其他區域同步狀態
6:30   完成
```

## 核心功能

### 1. 版本管理

```typescript
// 註冊新版本
manager.registerVersion({
  versionId: 'v1.2.3',
  applicationId: 'flash-sale-api',
  semver: '1.2.3',
  deployedAt: new Date(),
  deployedBy: 'ci-system',
  checksum: 'sha256-hash',
  features: ['multi-region', 'failover'],
  rollbackable: true,
  status: 'pending'
})

// 查詢所有版本
const versions = manager.getAllVersions()
```

### 2. 部署計劃

```typescript
// 創建部署計劃
const plan = manager.createDeploymentPlan(
  'v1.2.3',  // 版本 ID
  ['us-east-1', 'eu-west-1', 'ap-southeast-1'],  // 目標區域
  'rolling'  // 部署策略
)

// 查詢所有計劃
const plans = manager.getAllDeploymentPlans()
```

### 3. 執行部署

```typescript
// 執行部署計劃
const success = await manager.executeDeploymentPlan(plan.planId)

if (!success) {
  console.error('部署失敗，已觸發回滾')
}

// 查詢部署狀態
const status = manager.getDeploymentStatus(planId, 'us-east-1')
console.log(`進度: ${status.progress}%`)
console.log(`狀態: ${status.status}`)
console.log(`健康: ${status.healthCheck.isHealthy}`)
console.log(`延遲: ${status.healthCheck.avgLatency}ms`)
```

### 4. 故障恢復

```typescript
// 執行回滾
const success = await manager.rollbackDeployment(planId)

if (success) {
  console.log('回滾完成，恢復到先前版本')
}

// 查詢同步狀態
const syncState = manager.getSyncState('us-east-1')
console.log(`已同步: ${syncState.isSynced}`)
console.log(`待同步變更: ${syncState.pendingChanges}`)
```

### 5. 依賴管理

```typescript
// 設置區域依賴
manager.setDeploymentDependency('eu-west-1', {
  regionId: 'eu-west-1',
  dependsOn: ['us-east-1'],  // 需要先部署到 US-East
  priority: 2
})

// 確保部署順序遵守依賴關係
```

## 部署策略

### Canary (金絲雀) 部署
- 10% 流量到新版本 (1 小時)
- 50% 流量到新版本 (2 小時)
- 100% 流量到新版本 (24 小時)

**優點：** 漸進式驗證、最小化風險
**缺點：** 部署時間最長

### Rolling (滾動) 部署
- 按序列逐個區域部署
- 每個區域 5 分鐘
- 保持高可用性

**優點：** 平衡、可控、風險低
**缺點：** 部署時間中等

### Blue-Green (藍綠) 部署
- 並行運行新舊版本
- 立即切換流量
- 快速故障轉移

**優點：** 快速、即時回滾
**缺點：** 資源消耗大

## 故障轉移機制

### 自動故障轉移條件

```
觸發條件：
├─ 部署失敗 (3 次重試後)
├─ 健康檢查失敗 (連續 3 次)
├─ 錯誤率 > 1% (持續 5 分鐘)
└─ P99 延遲 > 500ms (持續 5 分鐘)

故障轉移步驟：
├─ 1. 停止舊版本流量接收 (5s)
├─ 2. 等待飛行中的請求完成 (10s)
├─ 3. 恢復舊版本配置 (30s)
├─ 4. 恢復數據狀態 (15s)
├─ 5. 驗證恢復成功 (10s)
└─ 6. 恢復流量接收 (立即)

總耗時：70s ~= 1 分鐘
```

## 事件系統

### 部署事件

```typescript
// 版本註冊
manager.on('version:registered', (version) => {
  console.log(`版本已註冊: ${version.versionId}`)
})

  console.log(`部署計劃已建立: ${plan.planId}`)

// 部署開始
manager.on('deployment:started', ({ planId, regions }) => {
  console.log(`部署開始，目標區域: ${regions.join(', ')}`)

// 區域部署開始
manager.on('deployment:region-start', ({ regionId, versionId }) => {
  console.log(`區域 ${regionId} 開始部署版本 ${versionId}`)

// 區域部署完成
manager.on('deployment:region-completed', ({ regionId, versionId }) => {
  console.log(`區域 ${regionId} 部署完成`)
})

// 部署完成
manager.on('deployment:completed', ({ planId }) => {
  console.log(`部署計劃 ${planId} 完成`)
})

// 部署失敗
manager.on('deployment:failed', ({ planId, failedRegion }) => {
  console.log(`部署失敗: ${failedRegion}，已觸發回滾`)
})

// 回滾開始
manager.on('rollback:started', ({ planId }) => {
  console.log(`回滾開始: ${planId}`)
})

// 回滾完成
manager.on('rollback:completed', ({ planId }) => {
  console.log(`回滾完成: ${planId}`)
})

// 同步完成
manager.on('sync:completed', (syncState) => {
  console.log(`區域 ${syncState.regionId} 同步完成`)
})
```

## 使用示例

### 完整工作流程

```typescript
const manager = new CrossRegionDeploymentManager()

// 1. 準備版本
const version: DeploymentVersion = {
  versionId: 'v2.0.0',
  applicationId: 'flash-sale-api',
  semver: '2.0.0',
  deployedAt: new Date(),
  deployedBy: 'ci-system',
  checksum: 'sha256-xyz',
  features: ['new-feature-a', 'new-feature-b'],
  rollbackable: true,
  status: 'pending'
}

manager.registerVersion(version)

// 2. 設置事件監聽
manager.on('deployment:completed', (data) => {
  console.log(`✅ 部署完成: ${data.planId}`)
})

manager.on('deployment:failed', (data) => {
  console.log(`❌ 部署失敗，已回滾: ${data.failedRegion}`)
})

// 3. 設置部署依賴
manager.setDeploymentDependency('eu-west-1', {
  regionId: 'eu-west-1',
  dependsOn: ['us-east-1'],
  priority: 2
})

// 4. 創建部署計劃
const plan = manager.createDeploymentPlan(
  'v2.0.0',
  ['us-east-1', 'eu-west-1', 'ap-southeast-1'],
  'rolling'
)

// 5. 執行部署
const success = await manager.executeDeploymentPlan(plan.planId)

// 6. 生成報告
if (success) {
  const report = manager.generateDeploymentReport()
  console.log(report)
}
```

## 故障排除

### 問題：部署超時

**症狀：** 部署超過預期時間
**原因：**
- 區域網絡延遲高
- 磁盤 I/O 操作慢
- 數據庫連接池用盡

**解決方案：**
- 增加超時時間上限
- 檢查區域網絡連接
- 擴展資源配置

### 問題：健康檢查失敗

**症狀：** 新版本部署後健康檢查不通過
**原因：**
- 新版本有運行時錯誤
- 依賴服務不可用
- 配置錯誤

**解決方案：**
- 檢查應用日誌
- 驗證依賴服務
- 檢查配置文件

### 問題：版本同步延遲

**症狀：** 區域間版本不一致
**原因：**
- 網絡分割
- 數據庫同步慢
- 隊列堆積

**解決方案：**
- 檢查網絡連接
- 增加數據庫複製倍數
- 清空隊列
