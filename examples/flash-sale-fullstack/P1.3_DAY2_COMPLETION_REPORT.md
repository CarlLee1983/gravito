## 架構設計決策

### 1. 批量提交策略
**選擇**：時間+大小雙重觸發

**理由**：
- 時間觸發（50ms）：確保低頻操作不會無限延遲
- 大小觸發（50 個）：確保高頻操作及時批處理
- 結合：平衡延遲和吞吐

### 2. 異步隊列管理
**選擇**：優先級感知的動態路由

**理由**：
- 關鍵操作（CRITICAL）立即執行
- 後台操作（LOW）批量異步化
- 隊列滿時自動降級到同步

### 3. 記憶體優化方向
**選擇**：字段佈局優化而非資料結構重設計

**理由**：
- 最小化代碼改動（無破壞性重構）
- 充分利用 V8 內聯緩存
- 無需改變 API 合約
