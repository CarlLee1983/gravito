**CSRF helpers fix (middleware-extra.test.ts):**

1. The `csrf helpers` describe block (lines 155-212) has 5 tests. Two fail intermittently:
   - "returns existing csrf token from cookie" — `expect(token).toBe('token123')` fails when `getCsrfToken` returns a different value
   - "csrfProtection rejects missing token" — `expect((res as any)?.status).toBe(419)` fails

2. Root cause: `getCsrfToken` calls `crypto.randomBytes(32).toString('hex')` when no cookie is present. In a concurrent test environment, the `makeContext()` helper creates a fresh context each time, but the `c.header('Set-Cookie', ...)` call modifies the context's header map. If another test in the same file is running concurrently (bun runs tests within a file serially, but the describe block state may leak from prior file runs in the same worker).

3. **Fix approach:**
   - Add `beforeEach` to the `csrf helpers` describe block that resets any shared state
   - Ensure `makeContext()` returns completely isolated objects (no shared references)
   - Add `afterEach(() => { mock.restore() })` if mocks are used
   - Check if the `makeContext` function (lines 11-50) uses any shared mutable state (like `setHeaders` object at line 17) — if shared, make it per-test
