Fix approach — use UNIQUE connection names instead of 'default':
1. In `AccountRepository.integration.test.ts`:

   - Update the `AtlasAccountRepository` to accept a connection name parameter, OR
   - If `AtlasAccountRepository` hardcodes 'default': Instead, move `DB.addConnection` into `beforeEach` (not just `beforeAll`) so the connection is re-established before EVERY test
   - Add `DB.addConnection('default', { driver: 'sqlite', database: ':memory:' })` in `beforeEach` to always reclaim the 'default' connection
   - Keep the `CREATE TABLE IF NOT EXISTS` pattern from Phase 2C

   - Apply the same pattern as AccountRepository
   - Ensure the `transactions` table is also recreated in `beforeEach`

**WebhookPlugin fetch mock fix:**

The WebhookPlugin tests (Plugins.test.ts lines 597-671) use `spyOn(globalThis, 'fetch')` with manual `fetchMock.mockRestore()` at the end of each test. If a test throws before reaching `mockRestore()`, the mock leaks to subsequent tests.

Fix approach:
1. Add `afterEach` to the `WebhookPlugin` describe block (line 572):
   ```typescript

     // Ensure fetch mock is always restored even if test throws
     mock.restore()
   })
   ```
2. Keep the existing per-test `fetchMock.mockRestore()` calls as they are (redundant but harmless)
3. Verify no other test in Plugins.test.ts is affected by the fetch mock leaking
