**File 1: packages/core/src/index.browser.ts line 111**

The browser barrel does not import GravitoConfig (it comes from PlanetCore which is server-only). Use a generic identity function instead:

Replace:
```typescript
export function defineConfig(config: any): any {
  return config
}
```
With:
```typescript
export function defineConfig<T extends Record<string, unknown>>(config: T): T {
  return config
}
```

This preserves the passthrough identity semantics while eliminating both `any` annotations. The `Record<string, unknown>` constraint matches the object-based config pattern without requiring PlanetCore imports.

**File 2: packages/core/src/observability/QueueDashboard.ts line 201**

WorkerPool is already imported as a type. The `config` property on WorkerPool is private, so direct property access is not possible without `as any`. The WorkerPool.getPoolStats() does not expose `workerThreads`. Use a biome-ignore suppression since the private property access is intentional internal plumbing:

Replace:
```typescript
poolSize: (workerPool as any).config?.workerThreads ?? 0,
```
With:
```typescript
// biome-ignore lint/suspicious/noExplicitAny: accessing private WorkerPool.config — no public accessor exists
```

Note: The alternative (adding a public getter to WorkerPool) would change WorkerPool's public API surface which is out of scope for a gap-closure plan. The suppression with reason is the correct minimal fix.

```typescript
    insert: (record: Record<string, unknown>) => Promise<void>
```
