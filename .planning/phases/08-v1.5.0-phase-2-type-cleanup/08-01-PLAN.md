- IF: hono/client types are valuable for users

- Rationale: Allows users to provide their own hono/client version

**Option B: Remove Entirely**
- IF: hono/client is not used or can be replaced
- THEN: Remove from dependencies, update imports, update documentation
- Rationale: Reduces dependency bloat
- Action: Remove from package.json, update imports/exports

**Option C: Move to Separate Adapter**
- IF: hono/client is optional functionality
- THEN: Create separate @gravito/beam-hono-client adapter package
- Rationale: Optional dependencies without forcing on all users
- Action: New package structure (deferred to future phase)

**Recommendation:** Option A (Type-Only peerDependency) — strategic value for RPC clients
