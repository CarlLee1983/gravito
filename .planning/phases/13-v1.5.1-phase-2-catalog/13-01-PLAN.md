   - Does search latency degrade with query complexity? (short query vs long query)

2. **Identify optimization candidates (document all, even if not implemented):**

   - **Add database indexes:**
     * Index on Product(categoryId) for category filtering
     * Index on Product(status) for status-based filtering
     * Index on Product(visibility) for access control
     * Index on Product(sku) for SKU lookup
     * Index on ProductVariant(productId) for variant queries
     * Index on ProductVariant(sku) for variant SKU lookup
     * Composite index on Product(categoryId, status) for filtered lists
     * Estimated impact: 30–50% faster filtered queries
     * Effort: 1–2 hours (add to schema, run migration)
     * Risk: Low (database-level change, no code changes)

   - **Lazy-load variants:**
     * Don't load variants in product list (separate query)
     * Load variants only when product details requested
     * Estimated impact: 40–60% faster list operations (if many variants)
     * Effort: 2–3 hours
     * Risk: Low (API contract stays same, implementation detail)

   - **Pagination optimization:**
     * Use keyset pagination instead of offset/limit (more efficient on deep pages)
     * OR add composite index (categoryId, createdAt) for stable sort
     * Estimated impact: 20–40% faster page N>100
     * Effort: 2–4 hours (schema + query changes)
     * Risk: Moderate (API changes if switching pagination style)

   - **Query result caching:**
     * Cache popular product lists (category view: top 10 categories)
     * Cache product search results (popular searches)
     * Cache category hierarchy (rarely changes)
     * Estimated impact: 50–90% faster for cached queries
     * Effort: 2–3 hours
     * Risk: Moderate (cache invalidation complexity)

   - **Full-text search indexes:**
     * Add full-text index to Product(name, description) for search
     * Estimated impact: 60–80% faster search queries
     * Effort: 1–2 hours (depends on database, some DBs built-in)
     * Risk: Low (search-specific optimization)

   - **N+1 query elimination:**
     * Audit for category tree loading (getting all subcategories)
     * Use single query with JOIN instead of loop
     * Estimated impact: 25–40% faster category operations
     * Effort: 1–2 hours
