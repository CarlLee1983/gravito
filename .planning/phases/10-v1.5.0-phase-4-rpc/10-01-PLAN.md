## Task 2: Strategy Decision

### Decision Framework

**Option A: Type-Only peerDependency (Recommended)**
- Rationale: RPC client types are valuable for type inference
- Action: Mark as optional peerDependency in beam/photon
- Migration: v2.0 plan to replace with native RPC system
- Cost: Keep Hono type dependency

**Option B: Remove Entirely**
- Rationale: hono/client not critical, native solution is better
- Action: Remove from all package.json entries
- Migration: Update imports, update users
- Cost: Potential breaking change if used

**Option C: Relocate to Adapter Package**
- Rationale: Optional functionality shouldn't be in core
- Action: Create @gravito/photon-hono-client adapter
- Migration: v2.0 move to separate package
- Cost: New package structure

**Recommendation:** Option A (Type-Only peerDependency)
- Strategic value for type-safe RPC clients
- Phase 2 already started this with beam
- Clear v3.0 migration path to native RPC

### Decision Documentation
```markdown
## hono/client Strategy Decision

**Current Usage:** [X imports found in Y packages]
**Strategic Value:** Type-safe RPC client definitions
**Risk of Removal:** [low/medium/high]

**Decision:** Type-only optional peerDependency
**Timeline:** Keep through v2.x, native RPC in v3.0
**Migration Path:** Users specify hono as peerDep if needed

**Packages Affected:**
- @gravito/photon (check if needed)
- @gravito/beam (already handled in Phase 2)
```

**Estimated Time:** 1 hour
