## Tech Debt

### Critical (publish-time)

**TD-01: Regular `dependencies` version ranges not updated (19 packages)**
The bump script only updates `peerDependencies`. 19 packages still have `"@gravito/core": "^2.0.6"` (or similar) in their regular `dependencies` block. At npm publish time, semver resolution will fail against the published 3.0.0.

Affected: atlas, plasma, stream, photon, quasar, astral, constellation, flare, freeze-react, impulse, launchpad, luminosity, monolith, nebula-s3, radiance, site, zenith, chromatic, enterprise.

Additionally, stream has `"@gravito/atlas": "^2.5.2"` in dependencies while atlas is now 3.0.0.

**Recommendation:** Update bump script or run a targeted fix before npm publish.

### Non-critical (code quality)

**TD-02: Atlas grammar layer bare throws (~122)**
Grammar.ts, SQLiteGrammar.ts, MongoGrammar.ts, NullGrammar.ts retain `throw new Error()`. These are in the query-builder path, not the I/O error path. They throw for invalid SQL construction (e.g., unsupported clause types), which are developer errors rather than runtime infrastructure failures.

**TD-03: Secondary bare throws in foundation Orbits (~16 total)**
- signal ReactMjmlRenderer.ts: 5 throws
- plasma RedisManager.ts/BunRedisClient.ts: 3-4 throws
- photon native middlewares: 4 throws

These are in secondary paths not on the hot error reporting path.

**TD-04: Health check self-registration gap (4 packages)**
dark-matter, quasar, constellation, nebula-s3 cannot self-register health checks — they have no `GravitoOrbit.install()` lifecycle. External health probes needed. Documented in 19-09.

**TD-05: Pre-existing build:dts failure**
`@gravito/stream#build:dts` fails with "Cannot find module @gravito/atlas" — predates v2.0.0.
