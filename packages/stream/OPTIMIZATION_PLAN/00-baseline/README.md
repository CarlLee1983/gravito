# Phase 0: 基準測試與分析

> **狀態**: 待執行  
> **預估時間**: 2-3 天  
> **依賴**: 無

## 📋 目標

建立性能基準測試套件，量化當前系統的性能指標，為後續優化提供對比基準。

## 🎯 測試項目

### 1. 吞吐量測試

- **單條推送性能**: 測量 `push()` 的延遲和吞吐量
- **批量推送性能**: 測量 `pushMany()` 在不同批次大小下的性能
- **消費性能**: 測量 `pop()` 和 `Consumer` 的處理速度
- **並發推送**: 測量多個並發 `push()` 操作的性能

### 2. 內存使用測試

- **序列化大小**: 測量不同 Job 類型的序列化後大小
- **內存佔用**: 測量不同驅動在處理大量 Job 時的內存使用
- **GC 壓力**: 監控垃圾回收頻率和暫停時間

### 3. 驅動特定測試

- **MemoryDriver**: 內存隊列的極限性能
- **DatabaseDriver**: 數據庫查詢性能、連接池效率
- **RedisDriver**: Redis 操作延遲、Lua 腳本性能
- **其他驅動**: Kafka, SQS, RabbitMQ 的性能基準

### 4. 持久化層測試

- **單條寫入性能**: 測量 `archive()` 的延遲
- **批量寫入性能**: 測量批量 `archive()` 的性能
- **查詢性能**: 測量 `find()`, `list()`, `search()` 的性能

## 📊 基準測試指標

### 性能指標

- **吞吐量**: Jobs/second
- **延遲**: P50, P95, P99 延遲
- **並發能力**: 最大並發處理數

### 資源指標

- **內存使用**: 峰值內存、平均內存
- **CPU 使用**: 平均 CPU 使用率
- **I/O 操作**: 數據庫/Redis 操作次數

## 🛠️ 實施步驟

1. **建立基準測試框架**
   - 使用 `bun:test` 或 `benchmark` 庫
   - 建立可重複的測試環境
   - 設定測試數據生成器

2. **實現測試用例**
   - 單條操作測試
   - 批量操作測試
   - 並發測試
   - 壓力測試

3. **收集基準數據**
   - 運行所有測試用例
   - 記錄性能指標
   - 生成基準報告

4. **分析瓶頸**
   - 識別性能瓶頸
   - 分析內存使用模式
   - 找出優化機會

## 📝 預期輸出

- `benchmark-results.json`: 基準測試結果數據
- `benchmark-report.md`: 基準測試報告
- `bottleneck-analysis.md`: 瓶頸分析報告

## 📈 量測指標與門檻

- **吞吐量**: Jobs/second（P50/P95/P99 延遲對應）
- **延遲**: P50/P95/P99（含空佇列與滿載情境）
- **資源**: CPU/記憶體峰值與平均、Redis/DB I/O 次數
- **可重現性**: 固定版本、固定資料集、固定硬體/Redis 設定
- **門檻**: 需產出可重現的基準曲線，作為後續 Phase 對比基準

## 🧪 測試矩陣

- **基準測試**: 單條/批量/並發 push + pop
- **壓力測試**: 長時間穩定性（>= 2 小時）
- **資料集**: 小/中/大 payload
- **驅動覆蓋**: Memory/Database/Redis（必要）、其他驅動（可選）

## 🔁 回滾與切換策略
