# @gravito/ripple 優化計劃

> Bun 原生 WebSocket 廣播模組優化改善計劃

## 執行摘要

本文件概述 `@gravito/ripple` 套件的全面優化計劃。該計劃分為 5 個階段，每個階段專注於特定的改善面向。

## 現況分析

### 套件概覽
| 項目 | 內容 |
|------|------|
| **版本** | 3.0.1 |
| **用途** | Bun 原生 WebSocket 廣播，提供頻道式即時通訊 |
| **程式碼行數** | ~1,587 行（含測試） |
| **測試覆蓋率** | ~70%（需提升） |
| **相依性** | 零外部 WebSocket 依賴（Bun 原生） |

### 核心元件

| 元件 | 行數 | 用途 |
|------|------|------|
| `RippleServer.ts` | 429 | WebSocket 伺服器核心邏輯 |
| `ChannelManager.ts` | 217 | 頻道訂閱管理 |
| `Channel.ts` | 153 | 頻道實現（Public/Private/Presence） |
| `types.ts` | 201 | TypeScript 型別定義 |
| `RedisDriver.ts` | 186 | Redis 驅動程式（橫向擴展） |
| `Broadcaster.ts` | 123 | 廣播事件 API |
| `OrbitRipple.ts` | 81 | Gravito 框架整合 |
| `BroadcastEvent.ts` | 67 | 廣播事件基類 |
| `LocalDriver.ts` | 58 | 本地驅動程式 |

### 整合點
- **OrbitRipple**: 與 Gravito PlanetCore 容器無縫整合
- **RedisDriver**: 支援多伺服器橫向擴展
- **Broadcaster**: 提供 Laravel Echo 風格的廣播 API

## 識別的問題

### 嚴重度分類

| 類別 | 問題 | 嚴重度 | 影響 |
|------|------|--------|------|
| 架構 | Broadcaster 使用全域狀態 | 🔴 高 | 難以測試、多實例困難 |
| 型別安全 | RedisDriver 使用 `any` 型別 | 🔴 高 | 失去型別保護 |
| 錯誤處理 | 缺乏結構化日誌系統 | 🟡 中 | 難以追蹤問題 |
| 錯誤處理 | `send()` 方法無聲失敗 | 🟡 中 | 難以診斷連接問題 |
| 效能 | 每次廣播重複序列化訊息 | 🟡 中 | CPU 浪費 |
| 測試 | 缺乏整合測試 | 🟡 中 | 跨元件協作未驗證 |
| 文件 | 缺少架構圖與故障排除指南 | 🟢 低 | 新開發者上手困難 |

### 整體評分

| 面向 | 評分 | 備註 |
|------|------|------|
| 架構設計 | 7.5/10 | 模組清晰，但全域狀態需改進 |
| 型別安全 | 8/10 | 良好，Redis 驅動需改進 |
| 錯誤處理 | 6.5/10 | 基本可行，缺乏結構化日誌 |
| 效能 | 7/10 | 預期內，有微最佳化空間 |
| 可維護性 | 7.5/10 | 結構好，但重複程式碼可清理 |
| 測試覆蓋 | 7/10 | 單元測試完整，缺整合測試 |
| 文件完整 | 8/10 | 充分，缺架構和故障排除文件 |
| **整體** | **7.5/10** | **生產就緒，優化空間明確** |

## 成功指標

### 量化目標
- [ ] 測試覆蓋率：70% → **90%+**
- [ ] 型別安全：消除所有 `any` 型別
- [ ] 錯誤追蹤：100% 錯誤有結構化日誌
- [ ] 效能：訊息序列化減少 50% 重複

### 質化目標
- [ ] 移除全域狀態，改用依賴注入
- [ ] 完整的 JSDoc 文件覆蓋
- [ ] 架構決策記錄 (ADR) 完成
- [ ] 故障排除指南完成
