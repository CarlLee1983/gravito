## 核心功能：Relationship Loader

### 背景與目標

**問題：** 在 MongoDB 中處理關聯資料時，常見的 N+1 查詢問題：

```typescript
// N+1 查詢問題範例
const posts = await Mongo.collection('posts').limit(10).get()

for (const post of posts) {
  // 每個 post 都執行一次查詢（N 次）
  const author = await Mongo.collection('users').find(post.authorId)
  const comments = await Mongo.collection('comments').where('postId', post._id).get()
}
// 總共：1 (posts) + 10 (authors) + 10 (comments) = 21 次查詢
```

**目標：** 實作類似 Laravel Eloquent 的 `with()` 機制，減少查詢次數：

```typescript
// 使用 Relationship Loader（目標）
const posts = await Mongo.collection('posts')
  .with('author', 'comments')
  .limit(10)
  .get()

// 總共：1 (posts) + 1 (authors) + 1 (comments) = 3 次查詢
```

## 技術方案設計

### 方案 1：應用層 JOIN（推薦）

**優點：**
- 實作簡單，易於理解
- 不依賴 MongoDB 聚合管道
- 效能可控，可加入快取
- 支援跨資料庫關聯

**缺點：**
- 需要多次查詢（但仍遠少於 N+1）
- 記憶體使用較高（需暫存所有 ID）

**實作流程：**
```
1. 查詢主要資料（如 posts）
2. 收集所有關聯 ID（如 authorId）
3. 使用 whereIn 批次查詢關聯資料
4. 在應用層組合資料
```

### 方案 2：MongoDB $lookup

**優點：**
- 單次查詢完成
- 資料庫層面處理
- 減少網路往返

**缺點：**
- 效能不確定（依索引而定）
- 只支援同資料庫
- 聚合管道複雜度高
- 難以快取

**實作流程：**
```
使用 MongoDB Aggregation Pipeline 的 $lookup stage
```

### 決策：優先實作方案 1

理由：
1. **彈性更高** - 可支援跨資料庫、跨連線
2. **效能可控** - 可加入快取層
3. **實作簡單** - 易於測試和維護
4. **向後相容** - 不改變現有 API

方案 2 可作為未來的進階選項提供。

## API 設計

### 基本用法

```typescript
// 單一關聯
const posts = await Mongo.collection<Post>('posts')
  .with('author')
  .get()

// posts[0].author = { _id: '...', name: 'John', ... }

// 多個關聯
const posts = await Mongo.collection<Post>('posts')
  .with('author', 'category', 'tags')
  .get()

// 巢狀關聯
const posts = await Mongo.collection<Post>('posts')
  .with('author.profile', 'comments.user')
  .get()
```

### 關聯定義

**選項 1：裝飾器模式（TypeScript）**
```typescript
class Post {
  @BelongsTo(() => User, 'authorId')
  author?: User

  @HasMany(() => Comment, 'postId')
  comments?: Comment[]
}
```

**選項 2：靜態定義**
```typescript
const relationships = {
  posts: {
    author: {
      type: 'belongsTo',
      collection: 'users',
      foreignKey: 'authorId',
      localKey: '_id'
    },
    comments: {
      type: 'hasMany',
      collection: 'comments',
      foreignKey: 'postId',
      localKey: '_id'
    }
  }
}

Mongo.defineRelationships(relationships)
```

**選項 3：內聯定義（最彈性）**
```typescript
const posts = await Mongo.collection('posts')
  .with({
    author: {
      collection: 'users',
      foreignKey: 'authorId',
      localKey: '_id'
    }
  })
  .get()
```

**建議：** 同時支援選項 2 和 3，優先使用選項 2（預先定義），必要時使用選項 3（動態定義）。

### 第一階段：核心實作（2-3 週）

#### 1. 建立關聯定義系統
```typescript
// src/relationships/RelationshipRegistry.ts
class RelationshipRegistry {

```

#### 2. 擴展 MongoQueryBuilder
```typescript
// src/MongoQueryBuilder.ts
class MongoQueryBuilder<T> {
  private relationshipsToLoad: string[] = []

  with(...relationships: string[]): this {
    this.relationshipsToLoad.push(...relationships)
    return this
  }

  async get(): Promise<T[]> {
    const results = await this.executeQuery()
    if (this.relationshipsToLoad.length > 0) {
      return await this.loadRelationships(results)
    }
    return results
  }

  private async loadRelationships(results: T[]): Promise<T[]> {
    // 實作關聯載入邏輯
  }
}
```

#### 3. 實作關聯載入器
```typescript
// src/relationships/RelationshipLoader.ts
class RelationshipLoader {
  async loadBelongsTo(results: any[], relationship: Relationship): Promise<void>
  async loadHasMany(results: any[], relationship: Relationship): Promise<void>
  async loadBelongsToMany(results: any[], relationship: Relationship): Promise<void>
}
```

### 第二階段：進階功能（1-2 週）

#### 1. 巢狀關聯
```typescript
// posts -> author -> profile
const posts = await Mongo.collection('posts')
  .with('author.profile')
  .get()
```

#### 2. 條件式載入
```typescript
const posts = await Mongo.collection('posts')
  .with('comments', (query) => {
    return query.where('approved', true).orderBy('createdAt', 'desc')
  })
  .get()
```

#### 3. 選擇欄位
```typescript
const posts = await Mongo.collection('posts')
  .with('author:_id,name,email')
  .get()
```

### 第三階段：效能優化（1 週）

#### 1. 關聯快取
```typescript
// 快取常用的關聯查詢結果
const posts = await Mongo.collection('posts')
  .with('author', { cache: true, ttl: 300 })
  .get()
```

#### 2. 批次大小控制
```typescript
// 控制 whereIn 的批次大小，避免查詢過大
const posts = await Mongo.collection('posts')
  .with('comments', { batchSize: 100 })
  .get()
```

## 關聯類型支援

### 1. BelongsTo（屬於）
一對一關聯，外鍵在當前文檔。

```typescript
// Post belongsTo User
{
  _id: '1',
  title: 'Hello',
  authorId: 'user123' // 外鍵
}

// 載入後
{
  _id: '1',
  title: 'Hello',
  authorId: 'user123',
  author: { _id: 'user123', name: 'John' } // 載入的關聯
}
```

### 2. HasMany（擁有多個）
一對多關聯，外鍵在關聯文檔。

```typescript
// Post hasMany Comment
{
  _id: '1',
  title: 'Hello'
}

// 載入後
{
  _id: '1',
  title: 'Hello',
  comments: [
    { _id: 'c1', postId: '1', content: 'Great!' },
    { _id: 'c2', postId: '1', content: 'Nice!' }
  ]
}
```

### 3. BelongsToMany（多對多）
多對多關聯，需要中間表。

```typescript
// Post belongsToMany Tag (through post_tags)
{
  _id: '1',
  title: 'Hello'
}

// 中間表
{ postId: '1', tagId: 't1' }
{ postId: '1', tagId: 't2' }

// 載入後
{
  _id: '1',
  title: 'Hello',
  tags: [
    { _id: 't1', name: 'JavaScript' },
    { _id: 't2', name: 'MongoDB' }
  ]
}
```

## 與 @gravito/mass 整合

### 型別安全

使用 TypeBox 定義關聯型別：

```typescript
import { Type } from '@gravito/mass'

const UserSchema = Type.Object({
  _id: Type.String(),
  name: Type.String(),
  email: Type.String()
})

const PostSchema = Type.Object({
  _id: Type.String(),
  title: Type.String(),
  authorId: Type.String(),
  author: Type.Optional(UserSchema) // 關聯欄位
})

type Post = Static<typeof PostSchema>
```
